# バイナリのグループ幅と修復方法

バイナリ→テキストの入力は、グループ幅を統一してください。

- 8ビット: `01000001 01000010` → `AB`
- 4ビット: `0100 0001 0100 0010` → `AB`。2グループで1バイトです。
- 4ビットと8ビットの混在: `0100 0001 01000010` → エラー

混在したグループを先頭の幅だけで処理すると、後続データの欠落や別のバイトへの変化が起こることがありました。現在は混在を検証時に拒否し、すべて8ビット、またはすべて4ビットにそろえる案内を返します。自動で連結・分割・補正したり、一部だけを結果として返したりはしません。以前の出力から失われたデータは復元できないため、元の入力を確認して幅を直してください。

## 修復するには

1. 元のデータが表すバイトを確認します。
2. すべて8ビットにそろえるか、各バイトを2つの4ビットグループにそろえます。たとえば上の混在例は、`01000001 01000010` または `0100 0001 0100 0010` に直すと `AB` になります。
3. バイナリ→テキストの入力欄を修正します。修正後に再計算されます。

エラー時も入力は保持されます。既存画面は成功した結果だけを表示・コピー対象にするため、混在エラーでは出力欄と「結果をコピー」ボタンは表示されません。

## 変わらない範囲

- スペース・コンマ・改行・タブなど、既存の空白区切りを使えます。
- 4ビットグループは偶数個必要です。0と1以外の文字、不正なグループ長、有効なUTF-8ではないバイト列は引き続き拒否します。
- テキスト→バイナリの出力、文字数・バイト数・バイト内訳は変更していません。
- 区切りなしの長いビット列を新たにデコードする機能は追加していません。複数バイトのデコードには区切りが必要です。
- 処理は既存どおりブラウザー内で行い、入力を送信・保存しません。

## 開発時の確認

`vp test run tests/unit/text-binary.test.ts` で、混在の順序と区切り、統一後の修復、部分結果を返さないこと、既存のエラーとUnicodeの往復変換を確認します。UIの手動確認では、正常入力→混在入力→統一後の入力の順に変更し、エラー時の入力保持、旧出力・コピーの非表示、修復後の再表示を確認してください。
