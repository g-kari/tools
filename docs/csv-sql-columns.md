# CSV → SQL の引用符・列数と空セル

`/csv-sql` は最初の CSV レコードの列数を基準に INSERT 文を生成します。
ヘッダーありではそのレコードが列名、ヘッダーなしでは最初のデータ行になります。

- 基準より列が多いレコードは、レコード番号・実際の列数・基準の列数を示すエラーにします。値を切り捨てた SQL や途中までの SQL は返しません。
- エラーのレコード番号は 1 から始まり、ヘッダーを含みます。引用符の中の改行はレコードを分けません。
- 列が不足する場合は、従来どおり SQL `NULL` で補完します。これは「空値・NULL を SQL NULL に変換」の設定にかかわらず適用します。
- 最後のカンマの後の空セルも列として保持します。明示した空セルは NULL 変換が有効なら `NULL`、無効なら `''` になります。

例えば `id,name\n1,alpha,EXTRA` は 2 番目のレコードが 3 列あるためエラーです。
ヘッダーを `id,name,note` に直せば `EXTRA` も含めて生成できます。
エラー中も入力は保持し、以前の SQL・統計を表示せず、コピーボタンを無効にします。

## 引用符のエラー

- 引用符で始めたセルは、閉じる引用符が必要です。
- 引用符を含む値は全体を引用符で囲み、値の中の引用符を `""` にします。
- 閉じた引用符の直後は、カンマ、改行、または入力の終わりにします。他の文字を別のレコードとして扱いません。
- エラーは 1 から始まる論理レコード番号と列番号で示します。ヘッダーも数えますが、引用符内の改行はレコード番号を進めません。途中までの SQL は返しません。

例えば `name\n"alpha"x` は 2 番目のレコードの 1 列目をエラーにし、`alpha` と `x` の 2 行へ変換しません。
`id,name\n1,"alpha` の閉じ忘れや、`id,name\n1,al"pha` の囲まれていない引用符もエラーです。
正しい引用符内のカンマ・改行・二重引用符は保持します。

文書全体の前後空白を取り除く既存の仕様、重複ヘッダー、数値・NULL・ブーリアンの自動変換仕様は変更しません。引用符の検証が、生成 SQL の外部データベースでの実行成功を保証するものではありません。

## 検証

合成データだけを使用します。生成した SQL を外部データベースへ送信しません。

```bash
npm test -- tests/unit/csv-sql.test.ts tests/unit/csv-sql-quotes.test.ts tests/unit/csv-sql-quotes-ui.test.ts tests/unit/release-notes.test.ts
npx vp check
npm test
npm run build
# ビルド済みアプリを別ターミナルで起動
npm run preview -- --port 8788 --host 127.0.0.1
# 起動後、別ターミナルで実行
CI=true BASE_URL=http://127.0.0.1:8788 npx playwright test tests/e2e/csv-sql.spec.ts tests/e2e/csv-sql-quotes.spec.ts --project=chromium
```

ユニットテストは全 4 ダイアレクト、個別・バッチ INSERT、ヘッダー有無、
末尾の空セル、LF/CRLF、引用符内のカンマ・改行、不足列の補完を対象にします。
不正な引用符の 3 種類と、引用符内の改行を挟んだエラーのレコード・列番号も確認します。
E2E 回帰テストは成功後のエラー、入力・フォーカスの保持、古い出力の非表示、コピー無効化、修正・クリア、NULL 設定の切り替えを対象にします。
