# JSON Linesのトークン保持

2026-10-10。対象は `/json-lines` の整形、圧縮、JSONL→配列、配列→JSONLの4操作。

`JSON.parse` 後の値を `JSON.stringify` すると、大整数・高精度小数が丸められ、`1e400` が `null` になり、重複キーが消える。既存 `/json` の `formatJson` / `minifyJson` を再利用し、入力のJSON文法を確認してから元の字句を出力する。

## 保持するもの

- 数値の字句: `9007199254740993`、`0.1234567890123456789`、`1e400`、`1e-400`、`-0`、`1E+03`等
- 文字列とキーの元のエスケープ
- メンバーの順序と重複、配列要素順、レコード順
- 1レコード1行。空行、CRLF、行番号、trim、無効な行の扱いは既存契約を維持

配列→JSONLは完全なJSON配列を先に検証し、文字列と入れ子の外にあるトップレベルのカンマだけで要素を分ける。各要素の圧縮後に改行で接続する。JSONL→配列は各行を検証して接続し、既存JSON helperでインデントする。解析済みのJavaScript値を出力に使わない。

`parseJsonLines().parsed` は既存のJavaScript値APIを維持しており、数値の精度を保証する表現ではない。変換結果は `raw` の元トークンから生成する。

## 境界

元の空白や改行のバイト単位の復元、重複キーの統合・解釈、数値の計算、任意サイズの入力の性能保証は行わない。JSON文法や配列要件を緩和せず、BOM/NBSPの既存行単位trimと配列入力のnative JSON検証を維持する。

PR251の `/json` 無損失整形でJSON Linesは対象外だった。PR246のレコード境界・フォーム状態保持とは別の、元トークン消失を修正する。共有 `/json` helperやネットワーク・認証・依存を変更しない。

## 検証

数値・escape・重複キーは `JSON.parse` 同士の比較でなく、元の文字列との完全一致を検証する。単体、実React UI、既存の外部通信禁止loopback Chromium fixtureと全ページE2Eに回帰を追加。大きな合成入力では境界・字句保持と実行時間を確認するが、時間閾値のCIテストは追加しない。
